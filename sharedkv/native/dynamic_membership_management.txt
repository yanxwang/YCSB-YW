SharedKV Architecture Specification: Unified Block Storage & Dynamic Membership
Version: 1.6 (Full Integration)
Status: Final Implementation Specification for High-Performance CXL KV-Store

===============================================================================
1. 物理布局：统一分块 (Unified Block, UB)
===============================================================================
取消原有的 Request Pool 与 Data Region 的边界，整个 CXL 内存为一个统一的块池。
- 物理单元：2KB 固定大小分块 (Block)。
- 寻址：使用 32 位 block_id。物理地址 = Base_CXL + (block_id << 11)。
- 零拷贝：Block 从请求进入到持久化存储，物理位置永不改变。

[数据结构]
struct alignas(64) UnifiedBlock {
    // --- Header (64B) ---
    uint32_t next_block_id;   // 哈希冲突链或大对象链接指针
    uint32_t key_hash;        // 预计算哈希值（用于快速指纹比对）
    uint16_t key_len;
    uint32_t val_len;
    uint8_t  is_external;     // 1: 溢出至 Spillover Area (>2KB)
    uint64_t gsn;             // 全局序列号
    uint64_t t0, t1, t2, t3;  // 全链路性能监控时间戳
    char     reserved[23];    

    // --- Data Area ---
    char data[];              // Key + Value (内联模式)
};

2. 动态成员管理：系统清单 (System Manifest)
===============================================================================
系统不再通过命令行静态指定线程数，而是通过 CXL 内存中的“真理来源”进行动态发现。

- 注册表位置：CXL 内存起始位置 (Manifest Area)。
- 线程描述符 (ThreadDescriptor)：
  存储 thread_id, status (JOINING, ALIVE, LEAVING, DEAD), 
  以及队列的 CXL Offsets (req_queue_off, resp_queue_off)。
- 路由机制：
  1. Synchronizer 监测 Manifest 中 ALIVE 状态的 Worker。
  2. 使用“一致性哈希 (Consistent Hashing)”将 Key 空间映射到 Worker 虚拟节点。
  3. 当 Worker 加入/退出时，仅受影响的哈希环片段进行数据索引迁移（由于 Block 统一，无需物理移动数据）。

3. 分级 ID 管理：块所有权交换 (Ownership Swap)
===============================================================================
为了消除对全局分配器的竞争，采用三级批发-零售模型。
Block 跨 Client 迁移是正常现象（Client A 插入的 key 被 Client B 更新时，
id_old 归还到 Client B），因此全局 Bitmap 不按 Client 分段，使用原子位操作。

[三级存储结构]

  Level 1 — LocalBlockCache (LBC)
    位置：DRAM，RT 私有
    结构：LIFO 栈，容量 4096
    访问者：仅 Request Thread（零同步开销）
    用途：RT 发请求时 pop 一个 block_id，纯本地操作

  Level 2 — FreeBlockQueue (FBQ)
    位置：DRAM，per-client
    结构：SPSC 环形队列，容量 4096
    生产者：Response Thread（回收 Worker 返回的 id_old）
    消费者：Request Thread（drain 到 LBC）
    用途：跨线程传递回收的 block_id，cache line bouncing 最小化

  Level 3 — CXL Bitmap (Global Reservoir)
    位置：CXL 共享内存，globalidmap 区域
    结构：位图，1 bit per block_id，总 ceil(total_blocks/8) 字节
    访问者：所有 RT（原子位操作：lock bts / lock btr）
    用途：全局 block_id 池，LBC 溢出时归还、LBC+FBQ 耗尽时批发
    优化：每个 Client 维护 scan_hint（上次扫描位置），减少竞争

[操作流程]

  Acquire（RT 取 block_id，发请求前调用）：
    1. LBC pop          → 最快路径，纯本地栈操作
    2. FBQ drain → LBC  → 中等路径，批量 pop 到 LBC（填满到 4096）
    3. Bitmap batch alloc(256) → 慢路径，扫描 bitmap 批量分配 256 个到 LBC

  Drain（RT 定期调用，保持 FBQ 可消费，防止回收链路死锁）：
    1. if LBC.top >= 4096:
         批量归还 LBC 底部 256 个 block_id → Bitmap（原子 set bit）
         LBC.top -= 256
    2. while LBC.top < 4096:
         FBQ.pop → LBC.push

  Recycle（Response Thread 回收 block_id）：
    push block_id → FBQ（不变，SPSC 单生产者写入）

[交换协议 (Swap Protocol)]
  - RT 从 LBC pop 获得 id_new，填充 key/val 到 UnifiedBlock[id_new]。
  - Worker 接收 id_new，在哈希链表中找到旧版本的 id_old。
  - Worker 将 id_new 挂入索引，并在 Response 中传回 id_old。
  - Response Thread 将 id_old push 到 FBQ。
  - RT drain FBQ → LBC（或 LBC 满时 → Bitmap），完成循环。

[死锁预防]
  旧设计中 LBC 容量 < FBQ 容量，RT 被 RequestQueue 堵住时 LBC 满、
  drain 成为 no-op、FBQ 填满、RespThread 卡住、整条流水线死锁。
  新设计中 LBC 满时归还 Bitmap，FBQ 永远能被 drain，循环不会断裂。

[Bitmap 操作]
  分配 (alloc_batch)：
    从 scan_hint 开始扫描 64-bit word，找 set bit（=可用 block）。
    对每个可用 bit 执行 lock btr（atomic test-and-reset），成功则收入 LBC。
    收集满 256 个或扫描到末尾为止。更新 scan_hint。
  归还 (free_batch)：
    对每个 block_id 执行 lock bts（atomic test-and-set），将 bit 置 1。
    批量操作，256 个一次。

4. 超长 Value 处理：溢出路径 (Spillover Path)
===============================================================================
- 阈值：Value > 1856 字节。
- 处理：
  1. Request Thread 在 Spillover Region 申请变长内存。
  2. UnifiedBlock 设置 is_external = 1，其数据区存储 64 位外部偏移量。
  3. Worker 仅操作 UnifiedBlock 索引，不触碰外部大数据，保持控制平面高效。
- 回收：当 id_old 被回收且 is_external == 1 时，同步释放外部内存。

===============================================================================
5. 性能优化要点 (CXL-Friendly)
===============================================================================
- 指纹过滤 (Fingerprinting)：在遍历链表前，先比对 UnifiedBlock 里的 key_hash，减少无效的 CXL 内存读取。
- 稀疏索引 (Sparse Index)：增加 Bucket 数量使负载因子 L < 0.2，以空间换延迟。
- 内存屏障 (Barriers)：
  - 写：填充 Block 后执行 _mm_sfence()，再更新指针。
  - 读：遍历链表前执行 _mm_lfence()。
- 对齐寻址：使用位移指令 (Shift) 替代乘法进行 block_id 到物理地址的转换。
